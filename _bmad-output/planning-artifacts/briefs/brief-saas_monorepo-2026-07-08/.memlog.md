- (decision) Foundation success = architecture + core features + GDPR proven; real product validation required but not part of foundation scope
- (decision) Cloud-agnostic deployment: Docker Compose (dev), Docker/K8s (prod); no vendor lock-in required; single model, multi-scale
- (decision) GDPR/PII compliance from Day 1: encryption, consent tracking, export/delete; MVP approach but no compliance debt
- (decision) Decouple foundation completion from real product validation. Foundation is complete when its own features + deployment + compliance are proven. Other apps built on it are separate products, out of scope.
- (decision) Config-driven menu: left-hand (modules + expandable sub-modules) OR top-horizontal (modules with hover-tooltips for subs). Admin section with role/module mapping (CRUD), user mgmt, user-role assignment (many-to-many). Themes/styles via stylesheet config.
- (decision) Licensing: Apache 2.0. Permissive, professional positioning, explicit patent grants for enterprise. Allows full commercialization of derivative apps while signaling quality and enterprise-readiness.
- (decision) Deployment: Docker Compose + Kubernetes validation required. Include scripts for packaging, deployment, seeding, smoke tests. Encryption: at-rest via database config (not testable); ensure in-transit TLS between web and BFF.
- (decision) Solo personal project. All design/scope decisions favor clarity, modularity, and solo-dev maintainability.
- (event) Validation complete. Applied structural reordering (Scope before Success Criteria), consolidated licensing rationale, standardized admin panel terminology, added launch transition. Brief polished and ready.
