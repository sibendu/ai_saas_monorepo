- (constraint) [ADOPTED] Monorepo structure with npm workspaces: apps/web (Next.js), apps/bff (Express), packages/shared-types. Locked by existing code.
- (constraint) [ADOPTED] Tech stack locked: Next.js 14+, Express BFF, Prisma 6.19.2, PostgreSQL, TypeScript 5.3.3. All strict mode. Existing code enforces.
- (constraint) [ADOPTED] Auth via NextAuth (embedded in web app), JWT sessions 30-day expiry, HttpOnly cookies. Multi-provider: email/password, Google OAuth, GitHub OAuth.
- (constraint) [ADOPTED] BFF as private service (not public). Web app fetches from BFF server-side. No auth layer between web & BFF (trust boundary). CORS restricted to WEB_APP_URL.
- (constraint) [ADOPTED] Database: PostgreSQL via Prisma ORM. Shared-types package exports interfaces used by web & BFF. Single source of truth for data shapes.
- (decision) AD-01: Paradigm = Monorepo BFF. Binds: web & BFF are separate concerns but share types; web owns auth, BFF owns business logic. Prevents: tightly-coupled frontend/backend, duplicate type definitions, auth logic drift.
- (decision) AD-02: Session storage = JWT only (no Redis invalidation). Binds: sessions are stateless; revocation requires token blacklist (deferred). Prevents: dependency on Redis; enables horizontal scaling.
- (decision) AD-03: Menu & role-based access. Binds: roles are stored in DB; modules & sub-modules are config-driven (JSON or relational); many-to-many user-role mapping. Prevents: hardcoded permission logic, tight coupling to UI.
- (decision) AD-04: Menu layout = two switchable modes (left sidebar vs top horizontal). Binds: layout config toggles rendering; responsive behavior consistent. Prevents: tight coupling to one layout; enables easy theming.
- (question) OPEN-Q1: Module nesting depth — flat list vs hierarchical? Current code shows modules with sub-modules (two-level). Confirm for Phase 1 or defer deeper nesting to Phase 2?
- (question) OPEN-Q2: Theme switching mechanism — config-driven (restart app) or admin panel dynamic switch? Affects UX, session state handling.
- (question) OPEN-Q3: Deployment targets — Docker Compose locally, Kubernetes for prod. Scripts & manifests included. Confirm K8s distribution (Kind local, EKS, DO, other)?
- (decision) AD-05: Module nesting = two-level max (modules + sub-modules). Binds: role-module mapping is flat; admin panel CRUD simpler. Prevents: over-engineering, N-level nesting complexity. Phase 2 can extend if needed.
- (decision) AD-06: Theme switching = config-driven (env var or config file). Binds: theme immutable during session; no client-side stylesheet swapping. Prevents: session state complexity, admin panel scope creep. Aligns with stateless design.
- (decision) AD-07: Kubernetes distribution = out of scope for foundation. Binds: foundation provides generic K8s manifests and deployment scripts (no provider-specific tooling). Prevents: vendor lock-in. User selects Kind/EKS/DO/other separately post-foundation.
- (event) Architecture spine + discussion guide finalized. All 12 ADs locked. Deferred items captured. Ready for epic/story creation.
