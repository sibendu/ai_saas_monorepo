# Story 5.2: Integrate CSS Variables with Tailwind Config

Status: review

## Story

As a SaaS foundation maintainer,
I want Tailwind theme tokens mapped to the CSS variables from the default theme stylesheet,
so that application code can use semantic Tailwind utilities such as `bg-primary`, `text-primary`, and `border-border` while theme files control the rendered values.

## Acceptance Criteria

1. `apps/web/tailwind.config.js` maps semantic colors to CSS custom properties from `apps/web/public/theme-default.css`.
2. Color mappings use Tailwind CSS 3-compatible color functions that preserve opacity modifiers, for example `rgb(var(--color-primary) / <alpha-value>)`.
3. Semantic utilities are available for at least primary, secondary, accent, background, surface, muted surface, text, muted text, subtle text, inverse text, border, strong border, focus ring, danger, success, warning, info, and soft status colors.
4. Tailwind font-family, font-size, font-weight, line-height, letter-spacing, spacing, border-radius, border-width, ring-width, box-shadow, and overlay/focus tokens are mapped to the matching CSS variables where Tailwind supports those theme keys.
5. Existing Tailwind default utilities remain available unless this story intentionally adds a semantic alias; do not replace the entire default Tailwind palette or spacing scale.
6. The actual repository file `apps/web/tailwind.config.js` is updated in place; do not create `apps/web/tailwind.config.ts` unless the project is separately migrated to a TypeScript Tailwind config.
7. No broad component class migration is included in this story. Existing hardcoded `indigo`, `purple`, `gray`, `red`, `green`, `yellow`, `white`, and `black` utilities may remain until a dedicated migration story.
8. A validation artifact proves the semantic utilities are generated by Tailwind, including examples for color opacity modifiers such as `bg-primary/80` and `text-danger/90`.
9. `npm run type-check --workspace=apps/web` passes after the config change.
10. `npm run build --workspace=apps/web` is run after type-check; any failure is documented with the exact failing command and cause.

## Dev Notes

### Scope Boundaries

- This story maps an existing CSS variable contract into Tailwind. It does not create the contract, create light/dark themes, load theme files, or migrate component class names.
- Story 5.1 is a prerequisite because it owns `apps/web/public/theme-default.css`. Current repo state at story creation time did not contain that file, while the 5.1 story file existed as a ready-for-dev artifact.
- Story 5.3 owns `theme-light.css` and `theme-dark.css`.
- Story 5.4 owns config-driven `<link>` loading from `apps/web/src/app/layout.tsx`.
- Story 5.5 owns custom-theme documentation and example theme files.

### Current Code State

- `apps/web/tailwind.config.js` currently uses CommonJS, scans `./src/pages`, `./src/components`, and `./src/app`, and has `theme: { extend: {} }`.
- `apps/web/postcss.config.js` already wires `tailwindcss` and `autoprefixer`; no PostCSS change is expected.
- `apps/web/src/app/globals.css` currently defines only legacy RGB variables `--foreground-rgb`, `--background-start-rgb`, and `--background-end-rgb`, then uses them in the body background.
- `apps/web/src/app/layout.tsx` imports `./globals.css` and uses `next/font/google` `Inter`; leave this alone for Story 5.2.
- `apps/web/public/theme-default.css` was missing at story creation time. The dev agent must verify Story 5.1 has been implemented before touching Tailwind mappings.
- `apps/web/src/config/navigation.ts` centralizes some menu classes in `menuUiConfig`, but it still uses hardcoded Tailwind utilities. This story should not update that file.
- `AppShell`, `TopMenu`, admin components, auth pages, dashboard, customers, tasks, and preferences contain many current `gray`, `indigo`, `purple`, `red`, `green`, `yellow`, `white`, and `black` utilities. Keep those utilities working by extending Tailwind instead of replacing defaults.
- Existing unit tests assert literal class names such as `bg-indigo-600`, `text-white`, `text-gray-700`, `hover:bg-gray-100`, `border-indigo-600`, and `bg-indigo-100`; broad class migration would require intentional test updates and is out of scope.

### Required Tailwind Mapping Shape

Use the repo's current JavaScript config format. A representative implementation shape:

```js
const variableColor = (name) => `rgb(var(${name}) / <alpha-value>)`

module.exports = {
  content: [
    './src/pages/**/*.{js,ts,jsx,tsx,mdx}',
    './src/components/**/*.{js,ts,jsx,tsx,mdx}',
    './src/app/**/*.{js,ts,jsx,tsx,mdx}',
  ],
  theme: {
    extend: {
      colors: {
        primary: {
          DEFAULT: variableColor('--color-primary'),
          hover: variableColor('--color-primary-hover'),
          soft: variableColor('--color-primary-soft'),
          strong: variableColor('--color-primary-strong'),
        },
        secondary: {
          DEFAULT: variableColor('--color-secondary'),
          hover: variableColor('--color-secondary-hover'),
          soft: variableColor('--color-secondary-soft'),
        },
        accent: variableColor('--color-accent'),
        background: variableColor('--color-background'),
        surface: {
          DEFAULT: variableColor('--color-surface'),
          muted: variableColor('--color-surface-muted'),
          strong: variableColor('--color-surface-strong'),
        },
        text: {
          DEFAULT: variableColor('--color-text'),
          muted: variableColor('--color-text-muted'),
          subtle: variableColor('--color-text-subtle'),
          inverse: variableColor('--color-text-inverse'),
        },
        border: {
          DEFAULT: variableColor('--color-border'),
          strong: variableColor('--color-border-strong'),
        },
        focus: variableColor('--color-focus-ring'),
        danger: {
          DEFAULT: variableColor('--color-danger'),
          soft: variableColor('--color-danger-soft'),
        },
        success: {
          DEFAULT: variableColor('--color-success'),
          soft: variableColor('--color-success-soft'),
        },
        warning: {
          DEFAULT: variableColor('--color-warning'),
          soft: variableColor('--color-warning-soft'),
        },
        info: {
          DEFAULT: variableColor('--color-info'),
          soft: variableColor('--color-info-soft'),
        },
        overlay: variableColor('--color-overlay'),
      },
      fontFamily: {
        body: 'var(--font-family-body)',
        heading: 'var(--font-family-heading)',
      },
      fontSize: {
        body: 'var(--font-size-base)',
        'body-sm': 'var(--font-size-sm)',
        'body-lg': 'var(--font-size-lg)',
        heading: 'var(--font-size-xl)',
        'heading-lg': 'var(--font-size-2xl)',
      },
      fontWeight: {
        normal: 'var(--font-weight-normal)',
        medium: 'var(--font-weight-medium)',
        semibold: 'var(--font-weight-semibold)',
        bold: 'var(--font-weight-bold)',
      },
      lineHeight: {
        tight: 'var(--line-height-tight)',
        normal: 'var(--line-height-normal)',
        relaxed: 'var(--line-height-relaxed)',
      },
      letterSpacing: {
        normal: 'var(--letter-spacing-normal)',
      },
      spacing: {
        'theme-xs': 'var(--spacing-xs)',
        'theme-sm': 'var(--spacing-sm)',
        'theme-md': 'var(--spacing-md)',
        'theme-lg': 'var(--spacing-lg)',
        'theme-xl': 'var(--spacing-xl)',
        'theme-2xl': 'var(--spacing-2xl)',
      },
      borderRadius: {
        'theme-sm': 'var(--border-radius-sm)',
        theme: 'var(--border-radius)',
        'theme-lg': 'var(--border-radius-lg)',
        'theme-xl': 'var(--border-radius-xl)',
        'theme-full': 'var(--border-radius-full)',
      },
```

### Latest Technical Information

- Tailwind CSS v3.4.17 is the current v3 docs version observed during story creation; the repo depends on `tailwindcss` `^3.4.0`. Use Tailwind v3 config syntax and do not migrate to Tailwind v4 `@theme`.
- Tailwind's v3 documentation says CSS variable color values should be defined as color channels without the color-space function when opacity modifiers need to work.
- Tailwind v3.1 added `<alpha-value>` placeholder support in config color strings, allowing mappings like `rgb(var(--color-primary) / <alpha-value>)`.
- Tailwind theme docs state `theme.extend` preserves defaults while adding new utilities; use this path for semantic aliases.
- Next.js serves files in an app-level `public` folder from the site root, so the 5.1 file at `apps/web/public/theme-default.css` will later be referenced as `/theme-default.css` by Story 5.4.
